# พรอมต์สตอรี่บอร์ด · เทคนิคพื้นฐานทั่วไป

> ด้านล่างคือ**มาตรฐานพื้นฐานทั่วไป**สำหรับการสร้างพรอมต์สตอรี่บอร์ด ใช้ได้กับทุกสไตล์ภาพ คำยึดสไตล์ การแมปอารมณ์ คลังคำแสง/เงา พื้นผิวฉาก ข้อห้ามด้านสุนทรียะ และเนื้อหาอื่นที่**เกี่ยวข้องกับสไตล์**ถูกกำหนดโดยเทคนิคเฉพาะสไตล์ (`director_storyboard`)

---

## โหมดที่รองรับ

มาตรฐานนี้รองรับผลลัพธ์เฉพาะ**โหมดความสอดคล้องภาพอ้างอิง**สองแบบเท่านั้น:

- **โหมด A**: Seedream (doubao-seedream)
- **โหมด B**: Nanobanana (Gemini)

> ⚠️ **ไม่สร้างพรอมต์แบบ text-to-image** ผลลัพธ์ทั้งหมดอิงจากเวิร์กโฟลว์**ภาพอ้างอิง (image-to-image / ControlNet / ความสอดคล้องตัวละคร)** เป็นพื้นฐาน

---

## หลักการยึดเนื้อหาตามตารางสตอรี่บอร์ด (สำคัญที่สุด)

การสร้างพรอมต์คือ**การแปลงรูปแบบ** ไม่ใช่**การเขียนสร้างสรรค์** ตารางสตอรี่บอร์ดเป็น**แหล่งเนื้อหาเดียว**ของพรอมต์ ข้อมูลภาพทั้งหมดต้องยึดตามแถวที่ตรงกันในตารางสตอรี่บอร์ดอย่างเคร่งครัด ปรับได้แค่รูปแบบการแสดงออกและถ้อยคำให้เข้ากับความต้องการของโมเดลสร้างภาพเท่านั้น

### หลักการหลัก: คำบรรยายภาพคือแกนหลัก ไม่ใช่วัตถุดิบ

ฟิลด์ "คำบรรยายภาพ" ในตารางสตอรี่บอร์ดบรรจุข้อมูลภาพทั้งหมดของช็อต เป็น**เนื้อหาหลัก**ของพรอมต์ คำสไตล์ คำคุณภาพภาพ คำแสง/เงา เป็น**ของตกแต่งเสริม** ทำหน้าที่รับใช้คำบรรยายภาพ เมื่อทั้งสองแย่งพื้นที่โควตา token กัน **คำบรรยายภาพมาก่อน** ยอมลดคำสไตล์ดีกว่าตัดองค์ประกอบภาพในคำบรรยายภาพออก

### กฎเหล็ก

1. **คำบรรยายภาพต้องคงไว้ครบถ้วน**: องค์ประกอบภาพทั้งหมดในฟิลด์ "คำบรรยายภาพ" ของตารางสตอรี่บอร์ด (ตัวเอก วัตถุ ความสัมพันธ์เชิงพื้นที่ รายละเอียดการเคลื่อนไหว ความสัมพันธ์กับกล้อง) ต้องปรากฏครบในเนื้อหาพรอมต์ **ห้ามตกหล่นแม้แต่รายการเดียว**
2. **แปลงความหมายเท่ากัน**: เมื่อแปลงฟิลด์ตารางสตอรี่บอร์ดเป็นพรอมต์ เปลี่ยนได้แค่รูปแบบการแสดงออก (ไทย↔อังกฤษ, ร้อยแก้ว↔คำสำคัญ, ภาษาเล่าเรื่อง↔คำบรรยายภาพ) **ห้ามเปลี่ยนความหมาย** ตัวอย่าง: ตารางสตอรี่บอร์ดเขียน "เงาเสาอาคารเข้มลึก" → พรอมต์ต้องแสดงโทนเงาเสาที่มืดนี้ ห้ามเปลี่ยนเป็นความหมายอื่นเช่น "อาคารหรูหรา"
3. **ห้ามคิดสร้างสรรค์เพิ่มเอง**: ห้ามเพิ่มองค์ประกอบภาพตกแต่งที่ตารางสตอรี่บอร์ดไม่ได้ระบุ (ถ้าตารางไม่ได้เขียนกลีบดอกไม้ร่วง พรอมต์ห้ามเพิ่มเอง); ห้ามตีความบรรยากาศฉากใหม่ (ตารางเขียน "เย็นชาดูถูก" ห้ามเปลี่ยนเป็น "เศร้าสร้อยเปล่าเปลี่ยว")
4. **คำสไตล์ขึ้นกับเนื้อหา**: คำยึดสไตล์ คำล็อกคุณภาพภาพ คำพื้นผิวฉาก เป็น**คำตกแต่งเสริม** รับใช้เนื้อหาภาพที่ตารางสตอรี่บอร์ดกำหนดไว้แล้ว ห้ามแย่งบทบาทหลัก — เมื่อคำสไตล์ขัดกับคำบรรยายเฉพาะในตาราง ให้ยึดตารางสตอรี่บอร์ดเป็นหลัก
5. **ตรวจสอบย้อนกลับทีละฟิลด์**: หลังสร้างพรอมต์แต่ละรายการ ต้องเทียบกับแถวที่ตรงกันในตารางสตอรี่บอร์ดทีละฟิลด์ ยืนยันว่าการแมปด้านล่างสะท้อนครบถูกต้อง:

| ฟิลด์ตารางสตอรี่บอร์ด | ต้องสะท้อนในพรอมต์ | จุดตรวจสอบ |
|-----------|---------------|--------|
| คำบรรยายภาพ | เนื้อหาหลักของส่วน 【SCENE】ในพรอมต์ | ตัวเอก ความสัมพันธ์เชิงพื้นที่ รายละเอียดสำคัญทั้งหมด **ไม่ตกหล่น** |
| ฉาก | จุดยึดสภาพแวดล้อมในส่วน 【SCENE】 | ประเภทฉากตรงกันหรือไม่ |
| ขนาดช็อต | คำจัดองค์ประกอบขนาดช็อต | ขนาดช็อตตรงกันหรือไม่ (ขนาดช็อตผสมให้ใช้ปลายเริ่มต้น) |
| แอ็กชันตัวละคร | ท่าทางและทิศทางของตัวเอก | ความหมายแอ็กชันตรงกันหรือไม่ ทิศทางระบุชัดเจนหรือไม่ |
| อารมณ์ | คำใบหน้าแสดงอารมณ์ | โทนอารมณ์ตรงกันหรือไม่ |
| บรรยากาศแสง/เงา | ส่วน 【LIGHTING】ในพรอมต์ | ทิศทางแสง แนวโน้มโทนสี ความสัมพันธ์มืด-สว่างครบถ้วนตรงกันหรือไม่ |

> ⚠️ **ตรวจสอบไม่ผ่าน = พรอมต์ใช้ไม่ได้** ต้องแก้ไขก่อนส่งออก รูปแบบความล้มเหลวที่พบบ่อยสุด: องค์ประกอบเฉพาะในคำบรรยายภาพถูกคำแม่แบบสไตล์ทับจนตกหล่น

## หลักการระบุเฟรมแรก

ภาพสตอรี่บอร์ดคือ**เฟรมอ้างอิงแรกของวิดีโอ** โมเดลควรตัดสินสถานะภาพของเฟรมนี้ตามความหมายของ "คำบรรยายภาพ" ในตารางสตอรี่บอร์ด ไม่ใช้แม่แบบ "ท่าเตรียมพร้อม" แบบตายตัว

**ตรรกะการตัดสิน**:

| ประเภทคำบรรยายภาพ | วิธีจัดการ | ตัวอย่าง |
|-------------|---------|------|
| **ช่วงเวลานิ่ง** (หยุดเดินเงยหน้ามอง, ยืนจ้องมอง, เอียงหัวยิ้มเย้ยเย็น, ก้มเขียนหนังสือ) | **สร้างตามคำบรรยายตรงๆ** ไม่แก้เป็นแอ็กชันอื่น | "ตัวละครหยุดเดินเงยหน้ามองบางสิ่ง" → พรอมต์เขียนตรงว่า "หยุดเดินเงยหน้ามองบางสิ่ง" |
| **กระบวนการแอ็กชันต่อเนื่อง** (เดินผ่านทางเดินยาว, ฟันดาบลง, หันตัวจากไป) | เอา**สถานะแช่แข็งของช่วงเริ่มต้น**ของแอ็กชัน (ไม่ใช่ท่าเตรียมพร้อมนามธรรม) | "ฟันดาบลง" → "ดาบยกขึ้นเหนือหัวแล้ว ปลายดาบชี้ลง กำลังจะฟันลงในอีกเสี้ยววินาที" |
| **การเคลื่อนกล้อง** (ค่อยๆ ซูมเข้าเป็นช็อตกลาง, ซูมออกเป็นภาพไกล, เฟดเข้า) | เอาขนาดช็อต**ฝั่งเริ่มต้น**เป็นองค์ประกอบเฟรมแรก | "ไกล→กลาง" → เฟรมแรกเอา "ไกลมาก" |
| **เอฟเฟกต์ทรานซิชัน** (เฟดจากจอดำ, ทรานซิชันแบบผสม) | คงคำบรรยายไว้แต่ระบุเป็นสถานะเปิดเรื่อง | "เปิดเรื่องเฟดจากจอดำ" → "ภาพค่อยๆ ปรากฏจากจอดำ เปิดเรื่องด้วยช็อตไกลมาก..." |

**เกณฑ์การตัดสิน**: กาลของคำกริยาหลักและความหนาแน่นการเล่าเรื่องในคำบรรยายภาพ

> ❌ **วิธีที่ผิด**: เปลี่ยนทุกแอ็กชันเป็นท่า "กำลังจะเกิดขึ้น" ทำให้ความหมายแอ็กชันจางลง
> - ตารางเขียน "หยุดเดินเงยหน้ามอง" → เขียนผิดเป็น "กำลังจะยกหน้าขึ้นมองไปข้างหน้า" (แอ็กชันถูกทำให้อ่อนลง)
> - ตารางเขียน "ยิ้มเย้ยเย็นจากที่สูง" → เขียนผิดเป็น "มุมปากกำลังจะยกขึ้น" (อารมณ์ถูกทำให้อ่อนลง)
>
> ✅ **วิธีที่ถูก**: ยึดคำบรรยายแอ็กชันในตารางสตอรี่บอร์ดตรงๆ เอาสถานะเริ่มต้นเฉพาะเมื่อแอ็กชันนั้นเป็นกระบวนการต่อเนื่องจริงๆ

## กฎการแปลงฟิลด์เป็นพรอมต์

| ฟิลด์สตอรี่บอร์ด | การแปลงในพรอมต์ |
|----------|----------------|
| คำบรรยายภาพ | **เนื้อหาหลัก**: แหล่งข้อมูลหลักของส่วน 【SCENE】ในพรอมต์ ต้องคงไว้**ทุก**ตัวเอก ชั้นความลึกเชิงพื้นที่ รายละเอียดสำคัญ ความสัมพันธ์กับกล้องที่มองเห็นได้ครบถ้วน แค่เปลี่ยนภาษาเล่าเรื่องเป็นรูปแบบคำบรรยายภาพ ห้ามลดองค์ประกอบสำคัญ ห้ามเปลี่ยนความหมาย ห้ามเพิ่มองค์ประกอบภาพที่ไม่มีในคำบรรยายภาพเอง |
| ฉาก | ผสานเข้าส่วน 【SCENE】เป็นจุดยึดสภาพแวดล้อม ซ้อนทับคำจำกัดพื้นผิวฉากจากเทคนิคเฉพาะสไตล์ |
| ขนาดช็อต | คำจัดองค์ประกอบกล้อง (ดูคลังคำขนาดช็อตด้านล่าง) ต้องตรงกับฟิลด์ "ขนาดช็อต" ในตาราง ขนาดช็อตผสม (เช่น "ไกล→กลาง") เอา**ปลายเริ่มต้น** |
| การเคลื่อนกล้อง | เป็นข้อมูลการผลิตสตอรี่บอร์ดเท่านั้น ไม่เข้าพรอมต์ ไม่ส่งออกหมายเหตุการเคลื่อนกล้อง |
| แอ็กชันตัวละคร | อิงจากฟิลด์ "แอ็กชันตัวละคร" จัดการตาม "หลักการระบุเฟรมแรก" ต้องคงความหมายแอ็กชันและป้าย `｜ทิศทาง:` ที่ระบุชัดเจนไว้ |
| อารมณ์ | อิงจากฟิลด์ "อารมณ์" เลือกคำใบหน้า/สายตาที่ตรงจากตารางแมปอารมณ์ของเทคนิคเฉพาะสไตล์ โทนอารมณ์ต้องตรงกับตาราง |
| บรรยากาศแสง/เงา | อิงจากฟิลด์ "บรรยากาศแสง/เงา" **แยกเป็นส่วนอิสระ** เขียนในส่วน 【LIGHTING】คงไว้ครบถ้วนทั้งทิศทางแสง แนวโน้มโทนสี ความสัมพันธ์มืด-สว่าง รายละเอียดพื้นผิว |
| บทพูด | ไม่เข้าพรอมต์ ไม่ส่งออก |
| เสียงประกอบ | ไม่เข้าพรอมต์ ไม่ส่งออก |
| ชื่อ/ID สินทรัพย์ที่เกี่ยวข้อง | ใช้อ้างอิงภายในสำหรับผูกภาพอ้างอิงเท่านั้น จัดการตาม "กฎการอ้างอิงสินทรัพย์ภาพ" |

## คลังคำขนาดช็อต (ทั่วไป)

| ขนาดช็อตที่ป้อน | โหมด B (Nanobanana) คำกล้องภาษาอังกฤษ | โหมด A (Seedream) คำภาพภาษาไทย |
|----------|-------------------------------|---------------------------|
| ไกลมาก/ไกลมากพิเศษ | `extreme wide shot, establishing shot` | องค์ประกอบไกลมาก ภาพรวมสภาพแวดล้อม ตัวละครเล็กจ้อยในฉาก |
| ไกล/เต็ม | `wide shot, full shot, full body` | เต็มตัวเข้าเฟรม องค์ประกอบไกล สัดส่วนคนกับฉากสมดุล |
| กลาง | `medium shot, cowboy shot, knee shot` | องค์ประกอบกลาง ตัวละครตั้งแต่หัวเข่าขึ้นไปเข้าเฟรม |
| ใกล้ | `medium close-up, upper body` | องค์ประกอบใกล้ ครึ่งตัวบนเข้าเฟรม พื้นหลังเบลอ |
| ครึ่งตัว | `half body shot, bust shot` | องค์ประกอบครึ่งตัว ตั้งแต่เอวขึ้นไปเข้าเฟรม ระยะชัดตื้น |
| คลับอัพ | `close-up, face focus` | องค์ประกอบคลับอัพ ใบหน้าหรือรายละเอียดขยายใหญ่ พื้นหลังเบลอลึก |
| คลับอัพมาก | `extreme close-up, macro detail` | คลับอัพมาก รายละเอียดเฉพาะจุดสุดขีด พื้นหลังเบลอ |
| ช็อตข้ามไหล่ | `over the shoulder shot, two shot` | องค์ประกอบข้ามไหล่ ตัวละครหน้าฉากหลังเบลอ ตัวละครไกลชัดเจน |

**การจัดการขนาดช็อตผสม**: ถ้าตารางสตอรี่บอร์ดเขียน "ไกล→กลาง" "กลาง→คลับอัพ" ฯลฯ ภาพสตอรี่บอร์ดเป็นเฟรมอ้างอิงแรก **เอาขนาดช็อตเริ่มต้นฝั่งซ้ายของลูกศร**

## มาตรฐานรูปแบบผลลัพธ์

แต่ละช็อตส่งออก**พรอมต์แค่โหมดเดียว** (เลือกอย่างใดอย่างหนึ่ง) ห้ามส่งออกทั้งโหมด A และโหมด B พร้อมกันในช็อตเดียว

**กฎการเลือกโหมด**:

| เงื่อนไข | เลือกโหมด |
|------|----------|
| โมเดลเป้าหมายคือ Seedream / ตระกูล Doubao | โหมด A (พรอมต์ภาษาไทย/จีน) |
| โมเดลเป้าหมายคือ Nanobanana / ตระกูล Gemini | โหมด B (พรอมต์ JSON ภาษาอังกฤษ) |
| ผู้ใช้ไม่ระบุโมเดล | ใช้โหมด A เป็นค่าเริ่มต้น หรือถามผู้ใช้ยืนยัน |
| สร้างเป็นชุด | คงโหมดเดียวกันตลอด ห้ามสลับกลางทาง |

**กฎเนื้อหาผลลัพธ์**:
- เลือกโหมด A: ส่งออกเฉพาะเนื้อหา `[Prompt]` (ไม่มีคำเชิงลบ Seedream ไม่รองรับ)
- เลือกโหมด B: ส่งออกเฉพาะเนื้อหา `[JSON Prompt]` (มีฟิลด์ `"negative"`)
- นอกจากเนื้อหาพรอมต์แล้ว ค่าเริ่มต้นไม่ส่งออก: หัวข้อช็อต คำอธิบายการผูกภาพอ้างอิง หมายเหตุบทพูด หมายเหตุเสียงประกอบ การตรวจสอบข้อจำกัด สรุปสินทรัพย์

## โครงสร้างพรอมต์ (คำบรรยายภาพมาก่อน)

### หลักการโครงสร้างโดยรวม

เนื้อหาพรอมต์ใช้**โครงสร้าง 3 ส่วน** เพื่อให้คำบรรยายภาพครองตำแหน่งหลัก:

```
【SCENE】→ บรรจุเนื้อหาภาพครบถ้วนจาก "คำบรรยายภาพ" + "ฉาก" + "ขนาดช็อต" + "แอ็กชันตัวละคร" + "อารมณ์" ของตารางสตอรี่บอร์ด (แกนหลัก ความหนาแน่นข้อมูลสูงสุด)
【LIGHTING】→ บรรจุแสง โทนสี ความสัมพันธ์มืด-สว่างจาก "บรรยากาศแสง/เงา" (แยกเป็นส่วนอิสระ ป้องกันถูกคำสไตล์เบียด)
【STYLE】→ คำยึดสไตล์ + คำล็อกคุณภาพภาพ + ประกาศข้อห้าม (ตกแต่งเสริม สั้นกระชับ)
```

> **หลักการจัดสรรพื้นที่**: ส่วน 【SCENE】เป็นส่วนที่มีความหนาแน่นข้อมูลสูงสุดและยาวที่สุด ต้องบรรจุองค์ประกอบภาพทั้งหมดจาก "คำบรรยายภาพ" ครบถ้วน; ส่วน 【LIGHTING】รองลงมา บรรจุบรรยากาศแสง/เงาแยกอิสระ; ส่วน 【STYLE】สั้นที่สุด ใส่แค่คำยึดสไตล์และคำล็อกคุณภาพภาพที่จำเป็น ลำดับ 3 ส่วนห้ามสลับ ความยาวห้ามกลับด้าน — ถ้าคำสไตล์ยาวกว่าส่วนภาพ ถือว่าผลผลิตล้มเหลว

### โหมด A: Seedream (API `reference_images`)

กลไก: ภาพอ้างอิงส่งผ่านพารามิเตอร์ API `reference_images` ใน prompt ใช้ `@图1` ผูกภาพอ้างอิงโดยตรง

โครงสร้าง Prompt:

```
@图1 คือ{ชื่อสินทรัพย์}{ประเภทสินทรัพย์} @图2 คือ{ชื่อสินทรัพย์}{ประเภทสินทรัพย์} ... ,

【SCENE】{จุดยึดฉาก}, {คำจัดองค์ประกอบขนาดช็อต}, {คำบรรยายภาพแปลงเต็ม——คงองค์ประกอบภาพ ความสัมพันธ์เชิงพื้นที่ แอ็กชันตัวเอก ทิศทาง อารมณ์ทั้งหมด}

【LIGHTING】{ทิศทางแสง}, {แนวโน้มโทนสี}, {ความสัมพันธ์มืด-สว่าง}, {รายละเอียดพื้นผิว}

【STYLE】{คำยึดสไตล์}, {คำล็อกคุณภาพภาพ}, ห้ามมีตัวหนังสือบรรยายนอกภาพ ลายน้ำ ข้อความ UI

รักษาลักษณะใบหน้า ทรงผม เครื่องแต่งกายของ @图N ให้ตรงกับภาพอ้างอิงทุกประการ
```

**กฎสำคัญ**:
- ส่วน 【SCENE】ต้องคงข้อมูลทั้งหมดจากฟิลด์ "คำบรรยายภาพ" ของตารางสตอรี่บอร์ดไว้ครบ **ห้ามลด**
- ในส่วน 【SCENE】ชื่อตัวละคร/ฉาก/อุปกรณ์**ต้องใช้ `@图N` แทน** (ไม่ใช้ชื่อตัวอักษร)
- ข้อมูลทิศทางต้องเขียนไว้ในส่วน 【SCENE】อย่างชัดเจน (เช่น "3/4 หันหน้าไปทางขวา")
- ไม่ต่อท้ายด้วยส่วนภาษาอังกฤษ "Based on the reference image... Generate a new scene..." (กลไก `@图N` รับหน้าที่ผูกภาพอ้างอิงแล้ว การต่อท้ายจะทำให้คำบรรยายภาพซ้ำสองชุดและขัดแย้งกันได้ง่าย)

> เนื้อหาจริงของ `[คำยึดสไตล์]` `[คำล็อกคุณภาพภาพ]` กำหนดโดย**เทคนิคเฉพาะสไตล์**

### โหมด B: Nanobanana (multimodal + JSON)

กลไก: ภาพอ้างอิงและ prompt ป้อนเข้าพร้อมกันแบบ multimodal, prompt ใช้ JSON แบบมีโครงสร้างเพื่อบังคับความสอดคล้องของตัวละคร

โครงสร้าง Prompt (กรอบตายตัว):

```json
{
  "role": "You are a cinematographer and storyboard artist. Maintain strict visual continuity across all shots.",
  "character_reference": [
    { "image": 1, "ref": "@图1", "description": "[คำบรรยายลักษณะสำคัญ: สีผม/ทรงผม/เครื่องแต่งกาย/รูปร่าง]" },
    { "image": 2, "ref": "@图2", "description": "[คำบรรยายลักษณะสำคัญ]" }
  ],
  "continuity_rules": [
    "Same wardrobe, hairstyle, face features across ALL shots",
    "Same environment, lighting style, color grade",
    "Only framing, angle, action, expression may change",
    "Do NOT introduce new characters not in reference images"
  ],
  "shot": {
    "scene_and_framing": "[จุดยึดฉาก + คำจัดองค์ประกอบขนาดช็อต]",
    "subject_and_action": "[แอ็กชันตัวเอก + ทิศทาง + อารมณ์ + องค์ประกอบภาพทั้งหมดจากคำบรรยายภาพ ใช้ @图N แทนชื่อตัวละคร/ฉาก]",
    "lighting": "[ทิศทางแสง + โทนสี + ความสัมพันธ์มืด-สว่าง + พื้นผิว]",
    "style": "[คำยึดสไตล์ + คำล็อกคุณภาพภาพ]"
  },
  "negative": "[แม่แบบคำเชิงลบ รวม no subtitles, no watermark, no UI text] (รายการคำเฉพาะกำหนดโดยเทคนิคเฉพาะสไตล์)"
}
```

**กฎสำคัญ**:
- ฟิลด์ `shot` แยกเป็น 4 ฟิลด์ย่อย บังคับให้คำบรรยายภาพครองตำแหน่ง `scene_and_framing` และ `subject_and_action` เพื่อป้องกันถูกคำสไตล์เบียด
- `subject_and_action` เป็นฟิลด์ที่มีความหนาแน่นข้อมูลสูงสุด ต้องคง "คำบรรยายภาพ" + "แอ็กชันตัวละคร" + "อารมณ์" ไว้ครบ
- ภาพอ้างอิงเป็นอินพุตรูปภาพ ไม่ใช่ข้อความ URL
- คำบรรยายตัวละครคงไว้ 1-2 ประโยคลักษณะสำคัญ หลีกเลี่ยงความยืดยาว

## มาตรฐานภาษาและคุณภาพทั่วไป

- โหมด A (Seedream) เน้นย่อหน้าภาษาธรรมชาติ
- โหมด B (Nanobanana) เน้นพรอมต์แบบ JSON มีโครงสร้างภาษาอังกฤษ
- พรอมต์เน้น "การแสดงเนื้อหา + ความคมชัดของภาพ" หลีกเลี่ยงคำที่คลุมเครือ
- ไม่ใช้ถ้อยคำที่ทำให้ภาพเบลอ (ดูตาราง "คำต้องห้ามที่ลดคุณภาพภาพ" ด้านล่าง)
- คำเชิงลบของโหมด B ส่งออกตาม "แม่แบบคำเชิงลบ" เฉพาะสไตล์ ทุกรายการต้องมี ห้ามละ; โหมด A ไม่ส่งออกคำเชิงลบ
- คำล็อกคุณภาพภาพส่งออกตามแม่แบบ "คำล็อกคุณภาพภาพ" เฉพาะสไตล์ ทุกรายการต้องมี

## กฎข้อความในภาพ vs ข้อความนอกภาพ

- **ข้อความนอกภาพ** (คำบรรยายใต้ภาพ ลายน้ำ การ์ดชื่อเรื่อง ข้อความซ้อนทับแบบ UI) → **ห้ามโดยเด็ดขาด** ต้องประกาศห้ามในส่วน 【STYLE】และคำเชิงลบ
- **ข้อความในภาพ** (อุปกรณ์ข้อความที่มีอยู่จริงตามธรรมชาติในฉาก: ตัวละครกำลังเขียนหนังสือ ตัวอักษรบนม้วนหนังสือ ป้ายจารึก จดหมาย ป้ายบอกทาง ป้ายร้านค้า) → **ถือเป็นอุปกรณ์ประกอบฉาก** เมื่อคำบรรยายภาพในตารางสตอรี่บอร์ดระบุชัดว่ามีเนื้อหาแบบนี้ ควรบรรยายการมีอยู่ของมันในส่วน 【SCENE】ตามปกติ ไม่ถูกจำกัดโดยกฎห้ามข้อความ
- **เกณฑ์ตัดสิน**: ข้อความนั้นมีอยู่**ภายในโลกของเรื่องราว**หรือไม่ ตัวอักษรบนป้ายจารึก = อุปกรณ์ในภาพ ✅; บทพูดตัวละครที่ด้านล่างภาพ = คำบรรยายนอกภาพ ❌

## คำต้องห้ามที่ลดคุณภาพภาพ (ใช้ร่วมกันทุกสไตล์)

| การเขียนที่ห้าม | พฤติกรรมของโมเดล | ทางเลือกที่ปลอดภัย |
|---------|---------|----------|
| `film grain` / เกรนฟิล์ม | ทั้งภาพเป็นเม็ดเกรนเบลอ | `subtle cinematic texture` / พื้นผิวภาพยนตร์เบาๆ |
| `imperfect focus` / โฟกัสไม่ชัด | ทั้งภาพหลุดโฟกัส | ลบออกโดยตรง |
| `edges not perfectly sharp` | ขอบภาพเบลอ | ลบออกโดยตรง |
| `slight natural deviation` | ความละเอียดทั้งภาพลดลง | ลบออกโดยตรง |
| `not completely stable` | ภาพเบลอ | ลบออกโดยตรง |
| `blurry background` (ใช้ผิด) | ตัวเอกเบลอตามไปด้วย | `background bokeh, subject in sharp focus` |
| `hazy` / `foggy` (ใช้ผิด) | ทั้งภาพเป็นหมอก | ใช้เฉพาะเมื่อต้องการเปอร์สเปกทีฟทางอากาศ พร้อมเพิ่ม `subject sharp` |
| โฟกัสนุ่ม / ความพร่ามัว | ความคมชัดโดยรวมลดลง | ลบออกโดยตรง |

> **หลักการหลัก**: เนื้อหาสามารถ "ไม่สมบูรณ์แบบ" ได้ (แสงไม่สม่ำเสมอ องค์ประกอบไม่สมมาตร) แต่คุณภาพภาพต้องคมชัด

## มาตรฐานการประมวลผลเป็นชุด

เมื่อผู้ใช้ป้อนตารางสตอรี่บอร์ดหลายแถว:

1. **ประมวลผลตามลำดับทีละแถว** ไม่ข้ามแถว ไม่รวมแถว
2. แต่ละช็อตส่งออกพรอมต์ของโหมดเป้าหมายเท่านั้น (Prompt หรือ JSON Prompt)
3. หากฉากเดียวกันมีหลายช็อตต่อเนื่อง **คำพื้นผิวฉากใช้ซ้ำได้** แต่อารมณ์/แสง/ขนาดช็อต/แอ็กชันต้อง**ประมวลผลอิสระทีละแถว**
4. ช็อตที่มีชื่อสินทรัพย์ที่เกี่ยวข้องเดียวกัน **คำระบุความสอดคล้องต้องตรงกัน**
5. ไม่ต่อท้ายส่วนที่ไม่ใช่พรอมต์ใดๆ (เช่น สรุปการอ้างอิงสินทรัพย์ หมายเหตุบทพูด/เสียงประกอบ การตรวจสอบข้อจำกัด)

## กฎการอ้างอิงสินทรัพย์ภาพ

ฟิลด์ `prompt` ของแต่ละช็อตต้องขึ้นต้นด้วย**ป้ายกำกับสินทรัพย์ภาพ** และ**ใช้ `@图N` แทนชื่อตัวละคร/ฉาก/อุปกรณ์ที่ตรงกันโดยตรงในเนื้อหาพรอมต์** เพื่อสร้างความสัมพันธ์ผูกโดยตรงระหว่างภาพอ้างอิงกับคำบรรยายภาพ กำกับตามลำดับการอ้างอิงสินทรัพย์ใน `associateAssetsIds` เริ่มจาก `@图1`

**รูปแบบ**: `@图1 คือ{ชื่อสินทรัพย์}{ประเภทสินทรัพย์} @图2 คือ{ชื่อสินทรัพย์}{ประเภทสินทรัพย์} ... , เนื้อหาพรอมต์ที่ใช้ @图N แทนชื่อตัวละคร/ฉาก`

**การแมปประเภท**:

| type สินทรัพย์ | คำประเภทกำกับ |
|-----------|------------|
| role      | ตัวละคร      |
| tool      | อุปกรณ์       |
| scene     | ฉาก       |
| clip      | คลิป       |

**กฎ**:
- เริ่มเลขจาก `@图1` เพิ่มขึ้นตามลำดับอาร์เรย์ `associateAssetsIds`
- ID สินทรัพย์ที่อ้างอิงแต่ละตัวต้องมีป้ายกำกับหนึ่งรายการ **ห้ามตกหล่น ห้ามเกิน**
- ชื่อสินทรัพย์ใช้ฟิลด์ `name` ของสินทรัพย์นั้นจากข้อมูล assets
- ประเภทสินทรัพย์กรอกตามตารางการแมปด้านบน
- ส่วนป้ายกำกับกับเนื้อหาพรอมต์คั่นด้วย `, `
- สินทรัพย์ต่อยอดใช้ `name` ของตัวเองต่อกับ `type` ของสินทรัพย์แม่
- **การผูกในเนื้อหา (สำคัญที่สุด)**: ในเนื้อหาพรอมต์ ทุกตำแหน่งที่เดิมควรมีชื่อตัวละคร/ฉาก/อุปกรณ์ **ต้องแทนที่ด้วย `@图N` ที่ตรงกัน** ไม่ใช้ชื่อตัวอักษรอีกต่อไป วิธีนี้ทำให้ภาพอ้างอิงกับตัวเอกในภาพมีความสัมพันธ์ชี้ตรงกัน หลีกเลี่ยงความกำกวมจากชื่อสินทรัพย์ไม่ตรงกับชื่อตัวละคร (เช่น เมื่อชื่อสินทรัพย์ต่อยอดไม่ตรงกับชื่อตัวละครเดิม ใช้ `@图N` เพื่อข้ามความกำกวมของชื่อไปชี้ตรงภาพอ้างอิงได้เลย)
- `@图N` เดียวกันสามารถปรากฏซ้ำได้หลายครั้งในเนื้อหา (เช่น ตัวละครปรากฏพร้อมกันทั้งฉากหน้าและในภาพสะท้อน)

**ตัวอย่าง** (สมมติ `associateAssetsIds="[A, B, C]"` ตรงกับ ตัวละคร ก.(role), ตัวละคร ข.(role), ฉากหนึ่ง(scene)):

❌ ผิด (เนื้อหาใช้ชื่อตัวอักษร ไม่เชื่อมกับป้ายกำกับด้านหน้า):

## กฎความต่อเนื่องของตำแหน่งและทิศทางตัวละคร

เมื่อสร้าง prompt แต่ละรายการ ต้องปฏิบัติตามข้อจำกัดความสอดคล้องของตำแหน่งและทิศทางตัวละครข้ามช็อตดังนี้

### หนึ่ง กฎการรับทิศทาง (รับจากตารางสตอรี่บอร์ด)

ฟิลด์ "แอ็กชันตัวละคร" ของตารางสตอรี่บอร์ดมีป้ายกำกับ `｜ทิศทาง:` ชัดเจนอยู่แล้ว เมื่อสร้างพรอมต์ **ให้ดึงมาใช้โดยตรงเป็นอันดับแรก** และเขียนคำระบุทิศทางที่ตรงกัน**อย่างชัดเจน**ลงใน prompt (เช่น `facing right` / `หันหน้าไปทางขวา`, `three-quarter view facing left` / `3/4 หันหน้าไปทางซ้าย`)

**ลำดับความสำคัญในการรับ** (สูง→ต่ำ):

| ลำดับ | แหล่งเบาะแส | ตรรกะการจัดการ |
|--------|---------|----------|
| **1** | **ป้ายกำกับ `｜ทิศทาง:` ในฟิลด์แอ็กชันตัวละคร** | ตารางสตอรี่บอร์ดระบุชัดแล้ว → **ใช้ตรงๆ** ไม่ต้องเดา |
| 2 | **คำระบุทิศทางชัดเจนในคำบรรยายภาพ** | คำบรรยายภาพระบุทิศทางตรงๆ (เช่น "หันหลังให้กล้อง" "มองออกไปนอกหน้าต่าง" "หันหน้าเข้าหาผู้ชม") → ใช้ตรงๆ (เฉพาะเมื่อไม่มีลำดับ 1) |
| 3 | **ความสัมพันธ์เชิงพื้นที่หลายตัวละคร (แกนสายตา 180°)** | ในฉากสนทนา/เผชิญหน้า ตัวละครสองฝ่ายหันหน้าเข้าหากัน: ตัวละครฝั่งซ้ายภาพหันขวา ตัวละครฝั่งขวาภาพหันซ้าย ล็อกไว้ทั้งฉากหลังตั้งฐานครั้งแรก |
| 4 | **นัยจากขนาดช็อต** | ช็อตข้ามไหล่: ตัวละครหน้าฉากหันหลัง/เอียงหลังให้กล้อง ตัวละครไกลหันหน้าเข้ากล้อง; คลับอัพ/ใกล้พูดคนเดียว: ค่าเริ่มต้น 3/4 ด้านข้าง |
| 5 | **ความหมายอารมณ์และการเล่าเรื่อง** | โดดเดี่ยว/ครุ่นคิด/รำลึก → เงาด้านข้างหรือ 3/4 ด้านหลัง; เผชิญหน้า/ซักถาม → หันตรงหรือ 3/4 หันหน้าเข้าหาอีกฝ่าย; หลบเลี่ยง/เขินอาย → เอียงหัวเล็กน้อยหลบสายตา |
| 6 | **ตรรกะเชิงพื้นที่ของฉาก** | ต้อนรับที่ประตู → หันหน้าออกประตู; มองวิว → หันหน้าไปทางวิว; ก้มเขียนหนังสือ → หันหน้าเข้าโต๊ะก้มหัว |

> **กรณีทั่วไปแค่อ่านลำดับ 1 ก็พอ** ตารางสตอรี่บอร์ดกำกับไว้ตั้งแต่ต้นทางแล้ว ลำดับ 2-6 ใช้เป็นการเดาสำรองเฉพาะเมื่อตารางสตอรี่บอร์ดไม่ได้กำกับไว้

**ขั้นตอนการรับ**:
1. อ่านเนื้อหาหลังป้ายกำกับ `｜ทิศทาง:` ในฟิลด์ "แอ็กชันตัวละคร" ของแถวปัจจุบันในตารางสตอรี่บอร์ด
2. ถ้าป้ายกำกับมีอยู่และครบถ้วน → ใช้ตรงๆ ข้ามลำดับถัดไป
3. ถ้าป้ายกำกับขาดหาย (เช่น แถวภาพเปล่า) → เดาตามลำดับ 2-6 ทีละข้อ
4. เขียนข้อมูลทิศทางที่ได้ลงในตำแหน่งคำบรรยายตัวละครที่ตรงกันใน prompt

**คลังคำทิศทาง**:

| ประเภททิศทาง | โหมด A (ไทย) | โหมด B (อังกฤษ) | ฉากที่ใช้ |
|---------|-------------|-------------|---------|
| หน้าตรง | หันหน้าตรงเข้ากล้อง | facing camera, front view | การประกาศตัวเอง เผชิญหน้าสายตาผู้ชมโดยตรง |
| 3/4 หน้าตรง | 3/4 ด้านข้างเอียงเข้ากล้องเล็กน้อย | three-quarter view facing camera | ตัวเอกบทสนทนา การสื่ออารมณ์ |
| ด้านข้างตรง | เงาด้านข้างเต็ม | profile view, side view | การพูดคนเดียว ครุ่นคิด เผชิญหน้าแบบเงา |
| 3/4 ด้านหลัง | 3/4 ด้านข้างเอียงหลัง | three-quarter back view | การจากไป ความห่างเหิน รำลึกความหลัง |
| ด้านหลัง | หันหลังให้กล้อง | back view, from behind | เข้าฉากลึกลับ การจากลา การมองไปไกล |
| หันหน้าไปทางซ้าย | หันหน้าไปทางซ้ายของภาพ | facing left | ตัวละครฝั่งขวาของเส้น 180° เป้าหมายฝั่งซ้าย |
| หันหน้าไปทางขวา | หันหน้าไปทางขวาของภาพ | facing right | ตัวละครฝั่งซ้ายของเส้น 180° เป้าหมายฝั่งขวา |
| ก้มหน้าเล็กน้อย | ก้มหน้าเล็กน้อย | slightly looking down | ความเศร้า ความรู้สึกผิด ครุ่นคิด |
| เงยหน้าเล็กน้อย | เงยหน้าเล็กน้อย | slightly looking up | ความยโส การเงยมอง ความคาดหวัง |

> ป้ายกำกับทิศทางต้องมีทั้ง**ทิศทางแนวราบ** (หันซ้าย/ขวา/กล้อง) และ**แนวโน้มก้ม-เงย** (ถ้ามี) เช่น "3/4 หันขวา เงยหน้าเล็กน้อย"

### สอง กฎการล็อกตำแหน่งและทิศทาง

- **ล็อกตำแหน่งในภาพ**: ตัวละครเดียวกันในฉากเดียวกันตลอดหลายช็อต ตำแหน่งซ้าย-ขวาในภาพ (ซ้าย/กลาง/ขวา) ต้องคงที่ ห้ามข้ามฝั่งโดยไม่มีเหตุผลเชิงเนื้อเรื่อง
- **รักษาแกนทิศทาง**: ฉากสนทนา/เผชิญหน้ายึดหลักแกนสายตา 180° — ตัวละคร A หันขวาก็คงหันขวาตลอดฉาก ตัวละคร B หันซ้ายก็คงหันซ้ายตลอดฉาก ใน prompt ต้องระบุคำทิศทางชัดเจน (facing left / หันหน้าไปทางซ้าย, on the left side of frame / ฝั่งซ้ายของภาพ ฯลฯ)
- **ความสม่ำเสมอของชั้นหน้า-หลัง**: ถ้าตัวละคร A อยู่ชั้นหน้าและตัวละคร B อยู่ชั้นกลางในช็อต N ช็อตถัดไปในฉากเดียวกันไม่ควรสลับความสัมพันธ์หน้า-หลังโดยไม่มีเหตุผล
- **การเปลี่ยนตำแหน่งต้องมีแอ็กชันเชื่อมต่อ**: เมื่อตำแหน่งตัวละครในภาพต้องเปลี่ยนจริงๆ (เช่น เดิน หันตัว) prompt ของช็อตก่อนหน้าต้องมีคำบรรยายแอ็กชันการเคลื่อนที่/หันตัวที่ตรงกัน ห้ามกระโดดตำแหน่งเฉยๆ
- **การเปลี่ยนทิศทางต้องมีแอ็กชันเชื่อมต่อ**: เมื่อทิศทางตัวละครต้องเปลี่ยนจริงๆ (เช่น หันหัว หันตัว) prompt ของช็อตปัจจุบันต้องมีคำบรรยายแอ็กชันการหัน (เช่น "ค่อยๆ หันหัวไปทางฝั่งซ้ายของภาพ") และแอ็กชันหันนี้ต้องตรงกับฟิลด์ "แอ็กชันตัวละคร" ในตารางสตอรี่บอร์ด ห้ามเปลี่ยนทิศทางเฉยๆ
- **รีเซ็ตได้เมื่อข้ามฉาก**: เมื่อเปลี่ยนไปฉากใหม่ทั้งหมด สามารถจัดสรรตำแหน่งและทิศทางในภาพใหม่ได้ แต่ต้องคงความสม่ำเสมอภายในฉากใหม่นั้น

### สาม ความสัมพันธ์ทางภาพของพื้นผิวสะท้อน

เมื่อในภาพมีตัวกลางสะท้อน (กระจก ผิวน้ำ โลหะเรียบมัน กระจกหน้าต่าง เลนส์กล้อง ฯลฯ) ให้ระวังกฎดังนี้:

- **การกลับด้านของภาพสะท้อน**: ทิศทางซ้าย-ขวาของตัวละครในภาพสะท้อนตรงข้ามกับตัวจริง (ตัวจริงหันขวา→ภาพสะท้อนหันซ้าย) prompt ต้องระบุความสัมพันธ์ทิศทางระหว่างตัวสะท้อนกับตัวจริงอย่างชัดเจน (เช่น "@图1 หันขวา ในภาพสะท้อนบนผิวน้ำ @图1 หันซ้าย")
- **พื้นผิวสะท้อนไม่เปลี่ยนตำแหน่งอ้างอิง**: ตำแหน่งในภาพของตัวละครยึดตามตัวจริงเป็นหลัก ภาพในพื้นผิวสะท้อนไม่นับเป็นการเปลี่ยนตำแหน่งตัวละคร
- **เนื้อหาในพื้นผิวสะท้อนต้องตรงกับตัวจริง**: เครื่องแต่งกาย ทรงผม สีหน้าของตัวละครที่เห็นในพื้นผิวสะท้อนต้องตรงกับตัวจริงในเฟรมเดียวกัน ห้ามคลาดเคลื่อน
- **ระยะชัดและความคมชัดของพื้นผิวสะท้อน**: ตามระยะห่างและวัสดุของพื้นผิวสะท้อน ภาพสะท้อนสามารถลดความคมชัดได้ตามความเหมาะสม (เช่น ความเบลอจากคลื่นน้ำ) แต่ต้องระบุไว้ใน prompt (เช่น "ภาพสะท้อนบนผิวน้ำบิดเบี้ยวเล็กน้อย")
- **จุดกระตุ้นการรับรู้**: เมื่อคำบรรยายภาพหรือสินทรัพย์ฉากมีองค์ประกอบสะท้อนแสง เช่น กระจก ผิวน้ำ ทะเลสาบ ลำธาร กระจก โลหะสะท้อนแสง กล้อง/การถ่ายวิดีโอ จะกระตุ้นกฎนี้โดยอัตโนมัติ

## ภาคผนวก: ตัวอย่างผลผลิตครบวงจร

ด้านล่างสาธิตขั้นตอนครบวงจรของช็อตหนึ่งจากอินพุตถึงผลลัพธ์ ให้ Agent ใช้อ้างอิง ตัวอย่างนี้ใช้ตัวยึดตำแหน่งนามธรรม (ตัวละคร ก., ฉากหนึ่ง, อุปกรณ์ X ฯลฯ) การใช้งานจริงให้แทนที่ด้วยเนื้อหาจริงจากตารางสตอรี่บอร์ด
